### Added

- Served the kernel32 synchronization breadth the single-thread containment world can carry faithfully (extends BPTK-010/101): the multi-object `WaitForMultipleObjects`/`WaitForMultipleObjectsEx` over the real object table with wait-any index and wait-all consume semantics (the old already-signaled stub is gone), the waitable-timer trio (`CreateWaitableTimerA|W`, `SetWaitableTimer`, `CancelWaitableTimer`, `OpenWaitableTimerA|W`) whose due time is the one wake the virtual clock can deliver deterministically, the named-object open family (`OpenEventA|W`, `OpenMutexA|W`, `OpenSemaphoreA|W` — `CreateSemaphoreA|W` now accepts a name, and `CreateEventA` reads its ANSI name as ANSI), the interlocked bitwise family (`InterlockedAnd/Or/Xor`, the pointer-family CAS and exchange, and a named refusal for `InterlockedCompareExchange64` whose 64-bit prior value cannot cross the EAX dispatch boundary), `SignalObjectAndWait`, the futex-style `WaitOnAddress`/`WakeByAddressAll|Single`, `SleepEx` and `SwitchToThread`, and the thread-exit rows the one live thread can carry (`ExitThread`, `GetExitCodeThread`, `FreeLibraryAndExitThread`). An infinite wait still names the world (`hle_wait_deadlock`) instead of spinning. The conformance case table carries one case per new export and the behavior tests pin the prior-value, consume, and timeout semantics the oracle does not inspect.
- Made the WASM tier share ONE guest memory with the interpreter, and measured what that is worth. `seedStatePlan` used to copy every region's byte into the WASM instance on every invocation and splice them back out, so one tier call cost O(total guest memory map) rather than O(instruction executed). `buildGuestContext64` now allocates every region as a view into one `WebAssembly.Memory` that the compiled module IMPORTS, so a tier transition is a register and rip handoff. On PuTTY startup to its frontier the tiered path went from 5921 ms to 646 ms against 256-285 ms interpreted — 23x slower becomes 2.3x slower — and the handoff itself measures 1.01x. The memory cannot grow (`maximum === initial`), because a grow would detach every region view. Sharing also removed the "discard a faulted run" safety net, so a fault now stops AT the offending access having performed none of its effects and is committable. Records in [the throughput log](doc/tier-throughput-log.md).
- Compiled an indirect `jmp`/`call` as a return-to-dispatch terminator instead of rejecting the whole function, taking Chocolate Doom's WASM-tier eligibility from 285/1155 (24.7%) to 667/1155 (57.7%) of candidate function entry. An indirect transfer is a PRE-TRANSFER stop: the block body runs at WASM speed, then the module stops before the transfer having performed none of its effects and reports that instruction's VA, because only the interpreter can tell an import slot from an ordinary pointer — dispatching an import as a plain call had produced an 8-byte `rsp` divergence against real PuTTY. Every tier exit now reports a resume rip.
- Drove the CRT-initializer, dialog-creation and message-pump specializations in the tiered runner instead of refusing them by symbol name (`lib/exec64.mjs` additively exports `serveImportStop64`, `resumeSpecialization64` and `specializationSentinel64`). Chocolate Doom went from stopping after **164 instruction** with `tier_unsupported_specialization` to running freely on the tier (measured on an idle machine it runs at 0.97x of pure interpretation — close, but the tier does not beat the interpreter on Doom), and PuTTY's frontier moved from a tier refusal to the real `ole32!CoInitialize` import — the same stop `runImage64` reaches, now pinned in the 1:1 test against the reference interpreter so a tier limitation cannot quietly become the frontier again.
- Committed the WASM-tier eligibility instrument (`tool/eligibility.mjs`) and the throughput log, so two number this project had been quoting from session memory are reproducible. Eligibility is a codegen measurement, not correctness and not playability. The log also derives what real-time playability actually costs — ~400,000 instruction per presented frame steady state, so 35 fps needs ~14 M ips against ~0.18 M ips today, a ~64x gap — and records that residency, not eligibility or compile cost, is the binding constraint: 98.3% of Doom's executed instruction still run in the interpreter.

### Fixed

- Encoded `utf16le` / `ucs2` in the browser `node:buffer` shim (`web/shim/buffer.mjs`), which had no wide-string case and fell through to the one-byte-per-char latin1 path, so `Buffer.from(string, "utf16le")` wrote half the bytes. Every guest wide string (module filename, wide argv, config path) then read back garbled every other byte, and a browser-run WAD-backed guest exited having found no IWAD on a mangled path compare. The shim-versus-`node:buffer` codec test now covers the `utf16le` / `ucs2` roundtrip it had silently omitted.
- Accepted any `ArrayBuffer` view as a staged host file, not only a Node `Buffer` (`lib/hle.mjs`): the browser reads files through `fetch().arrayBuffer()`, yielding a plain `Uint8Array` that the `Buffer.isBuffer` guard was silently dropping. A non-Buffer view is now normalized to a zero-copy `Buffer` over the same memory and reads identically.
